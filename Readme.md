# TPU-MLIR Auto Converter Developer Guide

This tool is designed to automatically convert ONNX / YOLO `.pt` models into `.bmodel` format for Sophgo TPU devices using TPU-MLIR.

Supported models:

* PaddleOCR DET
* PaddleOCR REC
* YOLO HBB
* YOLO OBB

---

# 1. Pipeline Overview

## PaddleOCR Pipeline

```text
PaddleOCR ONNX
↓
Read YAML Config
↓
Extract Preprocess
↓
model_transform
↓
model_deploy
↓
BMODEL
```

## YOLO Pipeline

```text
YOLO .pt / .onnx
↓
If .pt → Ultralytics export ONNX
↓
Save ONNX copy
↓
If YOLO OBB → transpose output
↓
model_transform
↓
model_deploy
↓
BMODEL
```

---

# 2. Main Features

* Auto export YOLO `.pt` to `.onnx`
* Auto convert ONNX → MLIR → BMODEL
* Auto start Docker Desktop
* Auto create Docker container
* Auto use `/workspace`
* Auto copy `.bmodel` from Docker to host
* Auto open result folder after conversion
* Save logs inside each run folder
* Generate `commands.bat` / `commands.txt`
* YOLO OBB output transpose:

  * from `1 x 6 x 8400`
  * to `1 x 8400 x 6`
* Support both YOLO `.pt` and `.onnx`
* Auto detect existing transpose node
* Auto skip duplicate transpose

# 8. YOLO Export Logic

Main function:

```python
export_yolo_pt_to_onnx()
```

Responsibilities:

1. Load `.pt`
2. Use `ultralytics.YOLO`
3. Export `.onnx`
4. Copy ONNX into run folder
5. Add transpose node for YOLO OBB

Internal export command:

```python
model.export(
    format="onnx",
    imgsz=640,
    opset=12,
    simplify=False,
    dynamic=False
)
```

# 9. YOLO OBB Transpose Logic

The script supports transpose for:

* YOLO `.pt`
* YOLO `.onnx`

Only `yolo_obb` models perform transpose:

```text
1 x 6 x 8400
↓
1 x 8400 x 6
```

Using ONNX node:

```python
Transpose(
    perm=[0, 2, 1]
)
```

Node name:

```text
Transpose_YOLO_OBB_Output
```

New output:

```text
output_transpose
```

YOLO HBB models are not modified.

The script automatically prevents duplicate transpose nodes.


# 12. TPU-MLIR Commands

## model_transform

Generated by:

```python
_transform_argv()
```

Example:

```bash
model_transform \
  --model_name yolo_obb \
  --model_def /workspace/results/xxx/best.onnx \
  --input_shapes [[1,3,640,640]] \
  --mean 0,0,0 \
  --scale 0.003921568627,0.003921568627,0.003921568627 \
  --pixel_format rgb \
  --mlir best.mlir
```

## model_deploy

Generated by:

```python
_deploy_argv()
```

Example:

```bash
model_deploy \
  --mlir best.mlir \
  --quantize F16 \
  --processor bm1684x \
  --model best_bm1684x_f16.bmodel
```

# 19. Common Errors

## Docker Not Running

Start Docker Desktop or let the script auto start it.

## model_transform Not Found

Usually means incorrect Docker image.

Fix:

```bash
docker rm -f model_conversion
docker pull sophgo/tpuc_dev:latest
```

## Incorrect ONNX Output Shape

For YOLO OBB check in Netron:

```text
output_transpose
1 x 8400 x 6
```

## INT8 Deploy Failure

Usually caused by missing calibration table.

# 22. Model Path Configuration

## Selecting Models from GUI

The GUI uses `tkinter.filedialog` to allow users to browse and select model files.

Supported model inputs:

* `.onnx`
* `.pt`

Main variables:

```python
self.onnx_path_var
self.yolo_pt_path_var
```

These variables store:

* ONNX model path
* YOLO PT model path

Example:

```text
D:\BUU\model\best.onnx
D:\BUU\model\best.pt
```

---

## Default Browse Folder

To change the default folder shown when clicking Browse:

```python
filedialog.askopenfilename(
```

Example:

```python
path = filedialog.askopenfilename(
    initialdir=r"D:\BUU\model",
    filetypes=[("ONNX", "*.onnx")]
)
```

---

## Default Model Path

To automatically preload a model path when GUI starts:

Find:

```python
tk.StringVar(value="")
```

Replace with:

```python
tk.StringVar(value=r"D:\BUU\model\best.onnx")
```

or:

```python
tk.StringVar(value=r"D:\BUU\model\best.pt")
```

Example:

```python
self.onnx_path_var = tk.StringVar(
    value=r"D:\BUU\model\best.onnx"
)
```
